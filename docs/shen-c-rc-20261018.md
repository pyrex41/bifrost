# Shen-C v0.3.0 adapter qualification, 2026-10-18

Bifrost now pins **Shen-C v0.3.0**, declares its bundled kernel as **43.1**,
and builds with C17, make and Python 3. The obsolete Boehm/pkg-config install
requirement is removed. Version probing uses `(version)`, since raw
`--version` identifies the port release. The C artifact target is now mapped
to `shen-c`, so `--shake --impls shen-c` executes Yggdrasil's native pipeline.

Branch `fix/shen-c-native-rc` is based on `b0dee048`. Other adapters keep their
community 42.2 kernels. Exact version cases select the declared kernel;
ordinary semantics and capability probes remain checked. The adapter remains
experimental; installation still requires `--force`.

## Live results

Darwin arm64, Go 1.27.0, released Shen-C v0.3.0 with suffix views off. The
frozen corpus records **68 executed PASS, 2 FAIL, 2 capability SKIP and
2 nonmatching-kernel SKIP**. The existing aggregate summary prints 72 pass
and 2 FAIL because it includes skipped rows. This is **not a green corpus**.

The runtime failures remain visible:

- `bounded-tail-sum-file` echoes a returned string after the program output.
- `hash-agrees-with-equality` returns false for equal integer/float values.

The old floating-format failure is resolved and version checks now pass.
Signed Int64 overflow is catchable in RC; the divergence case exposes exact
`Integer overflow` text and retains the other ports' true/false buckets.
An unrelated error still fails.

The artifact controls use the companion Yggdrasil RC builder and a Shen-Go
**42.2** stage-1 host at `1f587de`. Their kernel is Yggdrasil's 42.2 slice,
rather than the CLI's bundled 43.1 kernel. Output oracles were checked
independently; agreement across one target would not establish correctness.

The companion record also retains an OPEN dynamic-load dependency: shaken
`tc-interp` omits `fix`, while its full-kernel control returns `normal-form = 7`.
See [Yggdrasil qualification](https://github.com/pyrex41/yggdrasil/blob/fix/shen-c-native-rc/docs/shen-c-rc-20261018.md).

## Reproduction and evidence

```sh
export BIFROST_SHEN_C=/path/to/shen-c-v0.3.0/bin/shen-c
go test -count=1 ./...
go run . --impls shen-c --json
```

The corpus currently exits 1 for those two failures. For artifact controls,
point `BIFROST_YGGDRASIL_BIN` at the updated CLI, `YGGDRASIL_SHEN_C_DIR` at
the released source checkout, and `YGGDRASIL_HOST` at a 42.2 host:

```sh
go run . --impls shen-c --shake --only bounded-tail-sum-file,recursion-fib-file,trap-cps-script --json
nix build .#default
```

## Post-release fix candidate

The two runtime failures above are corrected in Shen-C's
[`fix/bifrost-corpus-gaps` candidate](https://github.com/pyrex41/shen-c/tree/fix/bifrost-corpus-gaps).
The complete unchanged corpus now reports **70 executed PASS, zero failures,
two capability skips and two kernel skips** against that candidate. Its
[qualification record](https://github.com/pyrex41/shen-c/blob/fix/bifrost-corpus-gaps/docs/qualification/bifrost-corpus-gaps-20261018.md)
binds source, generated kernel, binaries and corpus identities, and records
fatal sanitizer plus full 136/0 suite results. These corrections are newer than
v0.3.0; this adapter's released installation pin is intentionally unchanged.
The C artifact's literal runtime-load dependency gap is also corrected in the
[Yggdrasil follow-up](https://github.com/pyrex41/yggdrasil/blob/fix/shen-c-native-rc/docs/dynamic-load-20261018.md).
The frozen v0.3.0 assessment above is retained as historical release evidence.
